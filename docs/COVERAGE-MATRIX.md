TimeZero's cohort-construction spine (010 code/NDC pull -> 020 event pull -> 030 index -> 040 enrollment pull -> 050 stitch -> 060 sequential attrition -> 070 baseline Table 1) is BUILT and correct, and its anti-hallucination architecture (LLM emits only a reviewable spec; deterministic byte-stable emitters; RAG-grounded verified=false codes; specReadiness hard gate) is the right, already-implemented foundation. The build reduces to two structural moves plus six analysis families. STRUCTURAL PREREQUISITE (do first, blocks everything): widen AnalysisRequest from {type,enabled,notes} into a per-family discriminated-union params object and wire emitSas to iterate spec.analyses and dispatch — today emitSas never reads spec.analyses at all, so no analysis type controls output. Then model followUp correctly: split it into a SHARED administrative observation-window-end (study end / enroll end / death / index+N) versus role-specific event times (discontinuation, switch) that are OUTCOMES, not shared censors, and never truncate the PDC/MPR denominator at discontinuation. PRIORITIES: P0 = cohort spine (done). P1 core-descriptive = the prevalence/incidence family (point + period prevalence, the shared prevalent-case washout module that backs both cumulative incidence and incidence rate, age/sex standardization, panel-churn-safe calendar trends) plus the incidence-rate table and the deterministic bivariate test-selection engine — mostly SQL-feasible, highest value, additive to the spine's denominators/index dates/person-time. P2 economic + patterns = the HCRU/cost module (which first requires the src/data/marketscan.ts schema-map additions: NETPAY-on-S, COPAY/COINS/DEDUCT/COB, CAP_SVC, FACPROF, I-table cost-sharing) with the PAY-vs-NETPAY cost identity and whole-cohort-$0 descriptive tables, and the treatment-episode substrate feeding PDC/MPR/persistence/LOT/switching/sequences — descriptive layers are SQL-feasible, adjusted-cost GLMs defer to SAS/R/Python. P3 causal + survival = new-user active-comparator design, PS estimation/matching/IPTW/overlap-weights with the mandatory SMD balance table + Love plot (SMD is the one inferential quantity fully SQL-computable and the ideal cross-check), the analysis-ready time-to-event dataset + KM/Cox/competing-risks/incidence-rate-regression, E-value, and the OS mortality-feasibility gate — model fitting is SAS/R/Python, SQL owns the deterministic datasets and descriptive estimators. P4 advanced = hdPS, negative-control empirical calibration, g-computation/DRS, time-varying/recurrent-event models, target-trial clone-censor-weight, GLM link diagnostics. CRITICAL PARALLEL TRACK: build the execution-based eval harness (Layer 7) — bundle a synthetic MarketScan-shaped dataset with planted ground truth, execute emitted SQL in PGlite and emitted SAS in CI, assert the structural invariants (monotonic attrition, num<=den, washout-zero-check, PY bounds, cost components sum to total, KM/CIF monotonicity, overlap-weight exact balance, SAS/SQL/R/Python cross-engine parity) and pin golden-file regressions per (spec,dialect) — because without it, correctness is architecturally bounded but not empirically proven. Ship the whole thing open source under AGPL-3.0 (Apache/MIT MCP shim + trademark), add a provider-adapter for local Ollama (32B-class minimum), and treat MCP as an additive model-agnostic integration surface, never a gate.

## Honest gaps — what MarketScan simply cannot do

- MORTALITY / OVERALL SURVIVAL is largely unascertainable on core CCAE/MDCR: the only native death signal is DSTATUS (discharge status on I/S/F), it is masked to missing from data year 2016 for privacy, and it captures IN-HOSPITAL death only — out-of-hospital death is never observed. OS is not supportable without a separately-licensed Merative Mortality Database (or pre-2016 years); the tool must gate OS behind a blocking-but-overridable feasibility check and substitute ascertainable endpoints (all-cause discontinuation, TTNT, disease-specific hospitalisation, composite claims events). DSTATUS death codes are exactly 20/40/41/42; 21/87 are law-enforcement/court transfers, NOT death. This cripples true death-competing-risk cumulative incidence (Aalen-Johansen/Fine-Gray with death as the competing event is infeasible) — treat death as a censoring-only caveat
- NO PERSISTENT PATIENT ID ACROSS EMPLOYERS: ENROLID is assigned by and unique WITHIN a data contributor; an employer change mints a NEW ENROLID with no reliable public crosswalk, so disenrollment is indistinguishable from loss to follow-up and enrollment-end censoring is mandatory and potentially INFORMATIVE (job loss correlates with health). You cannot claim lifetime continuity across a contributor boundary; the independent-censoring assumption underlying KM/Cox/Fine-Gray is structurally dubious and must be flagged for sensitivity analysis. (Intra-contributor you CAN follow a person across health-plan changes; the break is at the employer/contributor and CCAE->MDCR aging-in boundaries)
- NO CLINICAL DEPTH — the PS/DRS can only balance MEASURED claims-derived covariates: there are no labs, no disease severity, no BMI, no smoking, no performance status, no vital signs, no results (BR-LIM-004). Confounding-by-indication is therefore RESIDUAL BY CONSTRUCTION, which is precisely why the E-value and negative-control empirical calibration are mandatory (not optional) deliverables — a good-looking positivity/overlap plot does NOT rule out unmeasured confounding
- CONVENIENCE-SAMPLE, NON-REPRESENTATIVE DENOMINATOR: CCAE/MDCR is a voluntary opt-in sample of employer-sponsored lives whose contributing employers/health-plans enter and exit every year, so the underlying population size and mix shift annually — raw count changes cannot be read as real-world change, prevalence/incidence are administrative/treated (undercount undiagnosed/uncoded disease), and there is no general-population denominator. Calendar-time trends MUST report the annual denominator, use rates per member-year, apply an identical fixed continuous-enrollment rule every year, and include a stable-contributor/fixed-cohort sensitivity analysis. CCAE is commercial (<65, elderly strata near-empty); MDCR is Medicare-Supplemental 65+ (opposite truncation) and is NOT general Medicare; do not generalize CCAE/MDCR churn to MDCD (contributing states change independently)
- COST IS PAID-AMOUNT ONLY, PERSPECTIVE-CONSTRAINED, AND HAS STRUCTURAL TRAPS: no charges/list prices, no true unit costs; MDCR severely understates cost because the Medicare-paid amount sits inside COB so NETPAY is not total cost; Set A/B extracts can leave gross PAY unpopulated (forcing a NETPAY fallback + limitation); capitated encounters have understated financials; clinician-administered (buy-and-bill J-code) drug cost placement (outpatient vs pharmacy) is a non-comparable spec choice; and adjusted-cost inference (GLM gamma/two-part/bootstrap) cannot run in warehouse SQL at all — it must hand a per-patient analytic dataset to SAS/R/Python
- PERSON-TIME AND UTILIZATION HAVE SILENT-OVERCOUNT TRAPS: person-time must be built from stitched day-level DTSTART/DTEND clipped to censoring — NEVER from month-level enrollment indicators (a single covered day flags the whole month, overstating exposure) or claim counts; the Inpatient (I) table is the case-level rollup of Inpatient Services (S) so summing both double-counts every admission (TOTNET is the sum of service-level net pay); FACPROF double-counts every hospital outpatient visit (one facility + one professional claim) and OMOP pipelines do NOT de-dup it; STDPROV is specialty not a visit key; the I table carries no hospital identifier (transfer/different-facility tests need S/F); DAYS counts overnights so a same-day stay = 0 and any '>=1 day' filter silently drops them
- ICD-9->ICD-10 TRANSITION (2015-10-01): code sets that cross the boundary need BOTH eras keyed on DXVER; coded incidence/prevalence can show artefactual jumps at the transition, and claims run-out depresses the most recent still-incomplete data year (truncate or flag). This is not a defect the tool can fix, only surface
- WAREHOUSE-SQL STATISTICAL CEILING (honest, but narrower than first stated): person-time, counts, crude rates, Wilson and Byar CIs, directly-standardized rates with normal-approx CI, all descriptive HCRU/cost tables, SMD/ESS/E-value, and even KM/Nelson-Aalen/CIF point estimates + Greenwood CIs + the log-rank statistic ARE emittable in stock Postgres/Snowflake (KM via the exp(SUM(LN(1-d/n))) window identity) — but anything needing a DATA-DEPENDENT inverse-CDF (exact-Poisson gamma/chi-square inverse, Clopper-Pearson beta inverse, gamma/Fay-Feuer standardized-rate CIs) or ITERATIVE model fitting (Cox partial-likelihood, logistic/Poisson/NB/gamma GLM, PS logistic, Fine-Gray, PH diagnostics, bootstrap, greedy PS matching) exceeds stock warehouse functions and must defer to SAS/R/Python — reported honestly as a capability boundary, not faked. (Greedy PS matching is additionally deferred because it is order-dependent/non-deterministic, which would violate TimeZero's byte-stable-emission guarantee)
- THE VERIFICATION LAYER THAT PROVES CORRECTNESS DOES NOT EXIST YET: the emitters PRINT QC/ATTRITION/level-check blocks but the repo bundles NO synthetic MarketScan dataset and NO runner that executes the generated SQL or asserts any invariant (Layer 7 is designed, unbuilt); and every analysis module beyond attrition/Table 1 is unemitted (emitSas stops at 070_baseline and never reads spec.analyses), so those modules' invariants cannot exist until the templates do. Until Layer 7 ships, 'it gives the right numbers' is architecturally bounded but not empirically demonstrated
- CITATION HONESTY: the user-cited figures (~94% syntactic-valid vs ~52% functionally-correct LLM code; ~15-26% analyst codelist agreement) are DIRECTIONALLY supported by the literature but were NOT sourceable to those exact numbers this session; the firm retrievable anchors are the Spider(~90%)->BIRD(~21-73%) text-to-SQL execution-accuracy collapse and the ~12.8/30 top-code overlap between analysts — cite those, or find the primary sources, before publishing the specific percentages

## Open-source / MCP recommendation

Ship TimeZero open source under AGPL-3.0 for the app/core engine (with the MCP server and provider-adapter under Apache-2.0/MIT plus a registered trademark and a lightweight CLA), because for this tool open source IS the audit mechanism a pharma vendor-risk team uses to verify the 'nothing leaves your machine' privacy claim — source-available/FSL would forfeit the OSI 'open source' label the trust pitch depends on, and AGPL uniquely makes a closed proprietary clone of a browser-served app legally impossible. The user conflates two separate mechanisms: 'connect to Ollama' needs a PROVIDER-ADAPTER layer (an 'openai-compatible'/native-Ollama backend using structured-outputs format=<schema>, not tool-calling, with client-side PDF-to-text pre-extraction), and it is impossible today because src/extract/anthropic.ts hardcodes the Anthropic Messages API and ignores the already-present settings.baseUrl field — build that adapter FIRST, it is the small lift that actually answers the question. MCP is a DISTINCT, additive integration surface (build it SECOND) that lets any agent host — Claude Desktop, Claude Code, or an Ollama-driven agent — drive TimeZero's six deterministic tools (extract_spec, review_spec/patch_spec, lookup_codes, generate_code, run_verification, export_bundle) over stdio (local-only for privacy; remote Streamable HTTP is self-host-only and clearly marked as leaving the local envelope); it is genuinely the cleanest way to make the tool model-agnostic but is NOT a prerequisite and must never gate the standalone app. The deterministic spec-then-code architecture is exactly what makes a weaker local model tolerable — the model only fills a reviewable spec, codes are RAG-grounded and forced to verified=false, and specReadiness() gates emission — so a weak local model degrades to 'more human correction at spec review,' never 'wrong SAS/SQL,' with the honest caveat that acceptable local extraction needs a 32B-class model (24GB GPU) while 7-8B pushes far more criteria into the review queue. Default the model picker to a frontier model (Claude Sonnet) with documented local-Ollama as a supported option, and note that browser-to-Ollama is blocked by https-to-http mixed-content and Ollama's default CORS restriction, so the clean local path is a local Node/MCP process talking to Ollama over loopback.
